# Sensor Link Demo

Wendy Lite native app written in C. It streams four JPEG test frames embedded in
the firmware image as MJPEG over sensor-link, no camera required, and blinks the
onboard WS2812 LED as a liveness indicator.

## Supported boards

* ESP32-C5-DevKitC-1
* ESP32-C6-DevKitC-1
* ESP32-C6-DevKitM-1
* ESP32-C61-DevKitC-1

## Building

```sh
wendy run
```

## Streaming

`app_main` registers a sensor-link delegate advertising one `CAMERA` channel
(channel 0, MJPEG, 800x600). On subscribe, `cam_loop` starts pushing frames
through `wendy_core_send_jpeg_frame()`, one in flight at a time, cycling through
the four embedded images; unsubscribe or a dropped client stops it.

`cam_capture` stands in for a camera driver: it exposes the interface a real one
would, but serves the embedded frames instead of an image sensor, handing out
the next one on every capture. Nothing above it knows the difference -- `cam_loop`
streams whatever it is given, and would drive a real sensor unchanged.

Frames are never copied. `cam_capture_retrieve_jpeg_frame()` hands out a pointer
to where the frame already lives, and every successful call must be paired with
exactly one `cam_capture_release_frame()`. Here that release does nothing -- the
frames are in flash and there is nothing to give back -- but honouring the
pairing is what keeps the same caller correct against a real camera, whose
frames must go back to the driver.

## Embedded frames

`main/frames/frame_0.jpg` .. `frame_3.jpg` are 800x600 SMPTE colour bars,
generated by GStreamer and embedded via `EMBED_FILES` in
[main/CMakeLists.txt](main/CMakeLists.txt). They are committed on purpose, so
building this project never requires GStreamer.

To regenerate them (only needed when changing the pattern, geometry or quality):

```sh
./tools/gen-frames.sh
```

JPEG quality is hardcoded at 65, which puts each frame at ~29 kB -- smpte needs
a quality well below jpegenc's default of 85 to stay inside the 30 kB budget.
`PATTERN`, `QUALITY`, `WIDTH`, `HEIGHT`, `FRAME_COUNT` and `MAX_BYTES` are knobs
at the top of the script. It prints the size of every frame it wrote and exits
non-zero if any of them busts the budget.

Access the frames from C via [main/frames.h](main/frames.h):

```c
#include "frames.h"

for (size_t i = 0; i < frames_count(); i++) {
    struct frame_span f = frames_get(i);
    // f.data points into memory-mapped flash, f.size is the JPEG length.
    // Valid for the lifetime of the app -- do not free it.
}
```

`frames_get()` returns an empty span (`{NULL, 0}`) for an out-of-range index.
`app_main` logs each frame's size and SOI marker at boot as a smoke test.
